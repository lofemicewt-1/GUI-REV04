# 页面切换与窗口缩放卡顿修复结果

日期：2026-09-28

## 实际修复

- `pages/awp1018_page.py`、`pages/awp1221_page.py`：模式切换后的空闲回调不再调用 `update_idletasks()`。原写法会在一个回调里同步耗尽后续布局和重绘，期间主循环不能及时处理输入。现在由已有 Configure 事件继续同步滚动区域。
- `app/navigation.py`：首页尺寸对齐不再嵌套刷新全部空闲任务。
- `app/application.py`：端口枚举和 Windows COM 兜底扫描移到单个后台线程；主线程每 25 ms 收取结果。重复刷新合并到当前扫描，销毁首页时取消 UI 回调，工作线程不访问 Tk。

当前工作区已有的其他未提交功能保持原有内容。本次产品源码差异单独记录在 `outputs/ui_responsiveness/changes.diff`，不把整个 Git 工作区差异归因于此次修复。

单元测试过程中，已有多 Tk 根窗口测试产生了数条销毁后的 `ttk::ThemeChanged` 提示；没有单元测试失败，实际应用响应回归未捕获 Tk 回调异常。

侧栏旧验证脚本使用启动前的绝对计时，在启动布局耗时较长时会让“隐藏、恢复、检查”接连过期执行。记录表明检查比恢复映射事件早约 10 ms，修复前代码也会触发该误报。已将恢复后的检查计时移到实际 `deiconify()` 请求之后，保留映射状态和像素检查。

首次 EXE 检查受沙盒进程访问限制影响，无法观察/关闭测试进程；在普通 Windows 权限下清理了本次测试启动的进程后，使用同一 EXE 完成上述验证。这次沙盒错误没有作为 EXE 启动故障计入结果。
