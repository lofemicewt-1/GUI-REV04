## 3. AWP1922 完整显示方案

- 顶部标题、可滚动主体、固定底栏分为三个布局区域。标题和底栏受可用视口宽度约束，不能被正文最小宽度整体推到屏幕外。
- 底栏采用内容驱动的响应式分组：宽屏寄存器区和通信/地址区同排；宽度不足时通信/地址区移到下一行；更窄时寄存器标签与输入框按完整字段分组换行，读写按钮保持可见，不截断值。
- AWP1922 主体宽屏维持控制区与日志区双列；空间不足时上下排列。日志工具栏允许换行，日志文本不应以默认字符宽度决定整页最小宽度；长日志仅在日志内部水平滚动。
- 控制区适度紧凑，日志承接剩余空间；避免仅放大两只下拉框来填满窗口。说明文字随容器宽度换行。
- 保留必要的局部滚动作为极窄窗口兜底，不能以“存在全局水平滚动条”作为截图尺寸下完整显示的验收依据。
- 共享底栏如需调整，须回归 1018、1221 及其余使用 make_merged_footer 的页面；不将未涉及页面重新设计。

## 4. Logo 与 PIEZO CONTROL 尺寸方案

- 暂定以当前同一窗口尺寸、同一缩放下的实测视觉尺寸为基准，Logo 与字标目标放大约 15%（允许根据截图在 10%—20% 内微调）。这是设计目标，不是已完成结果。
- 公司 Logo 使用原始 assets/logo_light.png、assets/logo_dark.png，保留纵横比及透明边缘，不拉伸，不裁剪公司名称或中文副标；不改 Windows 标题栏小图标或 EXE 图标。
- 改善图片缩放精度，避免整数 subsample 在邻近尺寸突然跳级；先复用已有可用图像能力，不为规划安装依赖。
- PIEZO CONTROL 保持右对齐、现有字体风格和主题文字色；按实际剩余宽度测量，窄屏可收缩到现有大小或将品牌区移至独立行，优先保证完整显示。
- 顶部高度、Logo、字标及页面标题一起协调；避免仅增加字体却造成 1922 标题进一步越界。检查 app/application.py 的通用字体刷新不会覆盖专用设置。

## 5. AWP1221 深色主题方案

1. 顶层 AWP1221Page.refresh_theme 调用基类，再向所有已创建模式页传递刷新，包含隐藏页；延迟创建的控件使用当前 ctx.colors。
2. AWP1221ModePage 刷新自身日志、滚动容器、rom_canvas 背景和边框，按当前参数重绘波形；传播到实际持有的波形生成器、编辑器等子组件，避免重复订阅日志或重建用户数据。
3. 普通 tk.Canvas/tk.Text/Frame 等逐个更新，覆盖绘图区、坐标与刻度、曲线、参数说明、选择高亮、插入光标、只读/禁用状态、Notebook 页和弹出窗口。ttk 样式变化不能代替这些控件的显式刷新。
4. 保留现有波形参数、选中项、日志内容、滚动位置与模式状态。主题重绘不得调用写入波形、读芯片或其他硬件操作。
5. 深色背景与文字对比度目标至少 4.5:1；曲线和关键边界须清晰可辨。深色中不残留白色大面板，浅色切回后恢复正确；不把所有颜色硬编码成同一种深色。

“跟随深色系统”本计划解释为跟随 GUI 已选择的深色主题；不扩展新增 Windows 系统主题自动检测功能。

## 6. AWP1921/AWP1923 固定底部与详细模式

### 6.1 固定区范围

- 底部沿用 1018/1221 的分组顺序：已有通用状态操作一组，寄存器读写一组，通信板/芯片地址等身份设置一组。将当前顶部通用控件迁移并复用其变量和回调；不凭空新增芯片操作。
- 底栏固定在可见内容区域底边，主体独立滚动。横向不足时按第 3 节分组换行；底栏高度变化后，主体获得剩余空间，不被覆盖。
- Button/Pump/Full 内的模式专属参数、波形、ADC 配置继续归属于各模式主体，不全部搬到底栏。这里的“相关设置”限定为通用寄存器操作及通信/地址/已有公共状态设置。

### 6.2 模式规则

| 当前模式 | 普通寄存器读写及通用底栏 | 详细模式入口 | 详细编辑区 |
| --- | --- | --- | --- |
| Button Mode | 固定显示 | 隐藏 | 隐藏且不生效 |
| Pump Mode | 固定显示 | 隐藏 | 隐藏且不生效 |
| Full Mode，未勾选 | 固定显示 | 可选 | 折叠 |
| Full Mode，已勾选 | 固定显示 | 可选 | 展开 |

- Full Mode 初次进入默认关闭详细模式；可保留用户在 Full Mode 的勾选偏好和编辑内容，但有效详细状态必须同时满足 current_mode == full_mode 与用户勾选。
- 离开 Full Mode 时，恢复普通地址和值编辑含义、普通读写权限；隐藏的详细寄存器不能继续接管 _active_register_address。可分别保留普通输入与详细编辑草稿，切换不自动发送命令。
- 统一门控用于地址解析、字段编辑提交、权限状态、主题/语言刷新以及显隐；避免只修改 show_mode 而遗漏其他回调。

### 6.3 详细区格式

- Full Mode 开启详细模式后，详细编辑区放在底部操作区上方，同属底部区域。顺序为寄存器选择与说明、位域编辑、固定读写/身份行。
- 位域保持现有 MSB→LSB 顺序、位号与值对应、保留位和只读/只写提示，不将位块任意换行导致上下位错位；窄屏使用位域区域自身的水平滚动。
- 详细区采用受可用高度限制的内部滚动，不无限向上挤压 Full Mode 主体；寄存器读写按钮和模式切换始终可达。极小窗口下允许详细区纵向滚动，底部基本操作保留。
- 不改变 pages/awp192x_registers.py 中寄存器定义与编码，仅调整呈现与有效状态门控；Full Mode 原有页面布局和长内容仍可完整滚动到末尾。
